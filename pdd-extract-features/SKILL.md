# PDD-Extract Features - 功能点提取技能

## 1. 技能概述

### 1.1 核心定位
从业务分析结果和PRD文档中提取功能点，生成标准化的功能点矩阵。

### 1.2 技能边界
- **输入**: 业务分析报告、PRD文档
- **输出**: feature-matrix.md (功能点矩阵)
- **不负责**: 规格编写、代码实现

## 2. 功能点分类

### 2.1 按复杂度分类

| 复杂度 | 代码 | 说明 | 开发时间 | 人工参与 |
|--------|------|------|---------|---------|
| **核心业务** | P0 | 核心业务流程，涉及多方审批 | 3-5天 | 高 |
| **重要功能** | P1 | 重要业务功能，有替代方案 | 1-2天 | 中 |
| **辅助功能** | P2 | 辅助性功能，易于实现 | 0.5天 | 低 |

### 2.2 按操作类型分类

| 类型 | 代码 | 说明 |
|------|------|------|
| **增** | C | Create，新增数据 |
| **查** | R | Read，查询/详情 |
| **改** | U | Update，修改数据 |
| **删** | D | Delete，删除数据 |
| **批** | B | Batch，批量操作 |
| **审** | A | Approve，审批流程 |
| **导** | E | Export，数据导出 |
| **流** | F | Flow，状态流转 |

### 2.3 按AI角色分类

| AI角色 | 代码 | 说明 | 人工参与度 |
|--------|------|------|-----------|
| **主导者** | AI-L | AI主导实现 | 低 |
| **协作者** | AI-C | AI与人工协作 | 中 |
| **审核者** | AI-R | AI辅助审核 | 高 |

## 3. 功能点提取流程

### Step 1: 分析业务用例

从业务分析报告中提取用例：
- 主要参与者
- 用例名称
- 基本流程
- 扩展流程

### Step 2: 识别功能操作

对每个用例识别操作：

```markdown
| 用例 | 操作 | 操作类型 | 复杂度 | AI角色 |
|------|------|---------|--------|--------|
| UC-001 转让申请 | 发起申请 | C | P0 | AI-C |
| UC-001 转让申请 | 查看申请 | R | P1 | AI-L |
| UC-001 转让申请 | 修改申请 | U | P1 | AI-C |
```

### Step 3: 识别页面/接口

```markdown
| 功能点 | 页面路径 | API路径 | 方法 |
|--------|---------|---------|------|
| FP-001 发起申请 | form.vue | /apply | POST |
| FP-002 查看申请 | detail.vue | /apply/{id} | GET |
```

### Step 4: 生成功能点矩阵

```markdown
# [模块名称] 功能点矩阵

## 1. 功能点汇总

| 功能点ID | 功能名称 | 页面/接口 | 操作类型 | 复杂度 | AI角色 | 依赖功能 |
|---------|---------|----------|---------|--------|--------|---------|
| FP-001 | 发起转让申请 | form.vue | C | P0 | AI-C | - |
| FP-002 | 查看转让申请 | detail.vue | R | P1 | AI-L | FP-001 |
| FP-003 | 修改转让申请 | form.vue | U | P1 | AI-C | FP-001 |
| FP-004 | 删除转让申请 | list.vue | D | P1 | AI-C | FP-001 |
| FP-005 | 审批转让申请 | approval.vue | A | P0 | AI-C | FP-001 |
```

### Step 5: 功能点详情

对每个P0功能点生成详情：

```markdown
## 2. 功能点详情

### FP-001: 发起转让申请

**基本信息**:
| 项目 | 内容 |
|------|------|
| 功能点ID | FP-001 |
| 功能名称 | 发起转让申请 |
| 所属用例 | UC-001 |
| 操作类型 | C (Create) |
| 复杂度 | P0 |

**功能描述**:
申请人填写转让申请表单，提交后进入审批流程。

**前置条件**:
- 用户已登录
- 用户有发起申请的权限

**后置条件**:
- 申请记录已创建
- 状态变为"待审核"
- 通知审批人

**输入字段**:
| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| companyName | String | 是 | 企业名称 |
| transferType | Enum | 是 | 转让类型 |
| evaluationValue | Decimal | 是 | 评估价值 |
| floorPrice | Decimal | 是 | 转让底价 |
| attachments | File[] | 是 | 附件 |

**输出信息**:
| 信息 | 说明 |
|------|------|
| applyId | 申请ID |
| applyNo | 申请编号 |
| status | 申请状态 |

**业务规则**:
- 转让底价 >= 评估价值 * 90%
- 必须上传相关附件
- 同一企业同一类型只能有一笔进行中申请

**测试策略**:
- 正向: 正常提交申请
- 异常: 底价低于限制、附件缺失、重复提交
```

## 5. Guardrails

### 5.1 必须遵守
- [ ] 功能点ID全局唯一
- [ ] 每个功能点必须有明确的操作类型
- [ ] 必须标注功能点依赖关系
- [ ] P0功能点必须有详细描述

### 5.2 避免事项
- ❌ 功能点遗漏关键业务操作
- ❌ 依赖关系形成循环
- ❌ 复杂度评估与实际不符

## 7. 人工审核规范

本Skill遵循PDD框架人工审核规范。

### 7.1 审核节点

功能点矩阵生成完成后，需要进行人工审核。

### 7.2 审核内容

| 审核项 | 说明 |
|--------|------|
| 功能点完整性 | 是否覆盖所有业务功能 |
| 复杂度评估 | P0/P1/P2 是否合理 |
| 测试策略 | 是否完整 |
| 依赖关系 | 是否正确 |

### 7.3 审核粒度

- **批量审核**：快速浏览整体，标记需详细审核的内容
- **关键功能点详细审核**：P0优先级、复杂状态转换、外部系统集成、敏感数据处理

### 7.4 审核结果

- **输出文件**: `review-features.md`
- **结果类型**: passed / rejected / conditional

### 7.5 关键功能点定义

- P0 优先级功能点
- 涉及复杂状态转换
- 涉及外部系统集成
- 涉及敏感数据处理
